# Current Data Authority Matrix

## Scope and evidence

This matrix describes the runtime after the data-authority enforcement batch. The audit traced SQLAlchemy models and routes in `apps/api/app`, direct SQLite access in `services/crm/system_services/unified_service.py`, agent tools, Excel gateways, the Google Sheets gateway, import/export routes, reset routes, and migration scripts.

The operational store is the CRM database selected by `DATABASE_URL`. In the current development deployment this is SQLite. `RAHMA_SYSTEM_DB_PATH` is the compatibility path used by the shared CRM service and must identify the same SQLite file.

## Conflicting paths discovered

1. `apps/api/app/services/importer.py` silently updated existing CRM rows and committed each sheet.
2. `apps/api/app/routes/travelers.py` refreshed CRM counters from Excel during list and export reads.
3. `GoogleSheetsApiGateway.get_demo_stats()` and `crm_preview()` could use Google data as an operational read source.
4. `UnifiedCRMService.sync_trip_to_sheet()` wrote both source and runtime workbooks.
5. Agent tools and passport metadata could bypass the CRM HTTP boundary and open the database directly.
6. Demo reset endpoints could run without an explicit demo-data flag.
7. Interaction and handoff IDs have both service-generated and route-generated forms.

Items 1 through 6 are blocked or constrained by this batch. Item 7 is documented migration debt and prevents a full production go decision.
