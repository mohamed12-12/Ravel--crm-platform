# Production Gap Report

Date: 2026-06-17

Question: what prevents client delivery?

Answer: the product can be demoed, but it should not be delivered as a production CRM/agent without closing the gaps below.

## P0: Critical

### P0.1 Split Source Of Truth

The product writes to SQLite and syncs to Excel/Google Sheets. Some views/stats still read workbook data. Sync failures can be swallowed or queued lightly.

Impact:

- Operators can see stale or conflicting data.
- Client trust risk.
- Hard to debug production incidents.

Required fix:

- Choose DB as source of truth.
- Move sheets to import/export/reporting only, or implement a durable integration service.

### P0.2 Sensitive Passport/Attachment Handling Is Not Production Safe

Passport fields exist and files can be uploaded locally, but there is no secure document model, encryption, malware scan, access control, retention, deletion, or audit trail.

Impact:

- Major compliance and reputational risk.

Required fix:

- Implement secure attachment/document service before collecting real passports.

### P0.3 No Real Booking Confirmation Workflow

Booking confirmation is a manual status update. Payment is a string field.

Impact:

- Staff can misrepresent draft bookings as confirmed.
- No financial proof or inventory finalization.

Required fix:

- Build payment/deposit and confirmation workflow with audit, receipt, and inventory transaction.

### P0.4 Weak Production Security

Admin routes and APIs need production-grade authentication, authorization, CSRF protection, audit logs, and secret management.

Impact:

- Unauthorized access to traveler PII and booking data.

Required fix:

- Add auth/RBAC/CSRF/session controls and audit logs before deployment.

### P0.5 Instagram Integration Is Placeholder Only

Webhook exists for verification/logging but no real inbound/outbound message handling, idempotency, retries, queue, monitoring, signature hardening, or human inbox.

Impact:

- Cannot deliver real Instagram automation.

Required fix:

- Treat Instagram as a separate production integration phase.

## P1: High

### P1.1 In-Memory Agent Sessions

Agent sessions live in process memory.

Impact:

- Restart loses conversations.
- No multi-worker support.

Required fix:

- Store sessions in database/Redis with state transition audit.

### P1.2 Direct SQLite And SQLAlchemy Mixed Writes

`UnifiedCRMService` uses direct `sqlite3` while routes use SQLAlchemy.

Impact:

- Transaction/session consistency problems.
- Harder migrations and testing.

Required fix:

- Consolidate persistence layer.

### P1.3 Runtime Schema Mutation

Passport columns and sync queue can be created at startup/runtime.

Impact:

- Uncontrolled schema drift.

Required fix:

- Move to explicit Alembic migrations.

### P1.4 Booking Holds Do Not Expire Or Release

Draft holds increment but no expiry/release workflow exists.

Impact:

- Inventory can become falsely unavailable.

Required fix:

- Add hold model, expiration worker, and cancellation release.

### P1.5 Handoff Does Not Guarantee Automation Stop

Queue entry does not equal channel automation lock.

Impact:

- AI may continue after human takeover in future channel integration.

Required fix:

- Add automation lock and case lifecycle.

### P1.6 Identity Merge Needs Audit And Guardrails

Merge moves records and marks aliases, but there is no robust audit/approval workflow.

Impact:

- Incorrect merges can damage customer history.

Required fix:

- Add merge audit, preview, undo strategy, and permissions.

### P1.7 ID Generation Is Not Production Safe

IDs are generated by scanning max existing values or per-trip counts.

Impact:

- Collision risk under concurrency.

Required fix:

- Use DB sequences/ULIDs or transaction-safe counters.

## P2: Medium

### P2.1 Lead Model Overloaded

Lead mixes inquiry, opportunity, automation state, and task.

Impact:

- Pipeline analytics and sales operations become unreliable.

Recommended fix:

- Separate inquiry/opportunity/task/case models.

### P2.2 Trip Model Too Thin

Trip has text price and notes but lacks structured package/pricing/discount/rules.

Impact:

- Hard to scale beyond demo.

Recommended fix:

- Add structured trip product/departure/pricing/inventory design.

### P2.3 Limited Recommendation Logic

Recommendations use trip type and availability only.

Impact:

- Agent cannot personalize meaningfully.

Recommended fix:

- Add destination, dates, budget, group size, customer preferences.

### P2.4 Passport Flow Does Not Validate Data

Passport expiry and number are collected as text.

Impact:

- Poor data quality.

Recommended fix:

- Add validation and review status.

### P2.5 Handoff Reason And Status Taxonomies Are Uncontrolled

Reasons/statuses are strings.

Impact:

- Reporting and automation logic are brittle.

Recommended fix:

- Use controlled enums/reference tables.

### P2.6 React Admin Prototype Is Incomplete

Identity resolver is wired; copy/handoff/settings are placeholders.

Impact:

- Client may confuse prototype for finished admin app.

Recommended fix:

- Either finish it or hide it from delivery scope.

### P2.7 Encoding/UI Polish Issues

Some templates show mojibake artifacts.

Impact:

- Demo polish and trust issue.

Recommended fix:

- Normalize encoding and replace corrupted symbols/text.

## P3: Nice To Have

### P3.1 Better CRM Dashboards

Add conversion, lead aging, booking funnel, handoff SLA, and revenue dashboards.

### P3.2 Copy Approval Workflow

Add copy versioning, approval state, and preview.

### P3.3 Customer Segmentation

Structured VIP/repeat/group/customer preferences.

### P3.4 Admin UX Refinement

Improve form validation, inline errors, mobile layout, and consistency.

### P3.5 Test Data Factory

Replace phase-specific fixture duplication with clean factories.

### P3.6 Operational Runbooks

Add runbooks for sync failures, duplicate merge, booking correction, and handoff escalation.
